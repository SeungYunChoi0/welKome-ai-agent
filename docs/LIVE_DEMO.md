# 라이브 검색 과정 데모

브랜치: `demo/live-pipeline`. 기존 `main`과 병합하지 않고 별도로 관리한다.

## 실행

```bash
cd /Volumes/Yun_ssd/Furiosa_Demo/SNU_Project/welKome_app_demo
bash run_demo.sh
```

브라우저에서 http://127.0.0.1:8001 을 열고 초기 로딩 후 **챗봇** 탭에서 질문한다.
기존 앱의 기본 포트 8000과 분리했다. 전체 화면 버튼으로 발표 화면을 펼칠 수 있다.
데스크톱은 기존 휴대폰 UI 옆에 검색 패널을, 좁은 화면은 아래에 패널을 표시한다.

다른 포트: `DEMO_PORT=8002 bash run_demo.sh`. 중지: 터미널에서 Ctrl+C.
`run_demo.sh`는 명시한 `DEMO_PYTHON` → 활성 conda/venv의 `python` → 로컬 `demo_env/bin/python` → PATH의 `python`/`python3` 순서로 선택한다.
서버에서는 기존 환경을 활성화한 뒤 실행하면 된다:

```bash
conda activate welkome
bash run_demo.sh
```

Python을 직접 지정하려면 `DEMO_PYTHON="$(command -v python)" bash run_demo.sh`를 사용한다.

현재 로컬 작업 폴더의 `.env`, 가상 환경, Git에 없는 모델·인덱스·메뉴 이미지는 기존 폴더의 파일에 심볼릭 링크로 연결되어 있다.
원본 폴더가 있어야 실행할 수 있다. `.env`를 편집하면 기존 앱에도 같은 설정이 적용된다.
다른 서버에 배포할 때는 README의 assets와 환경 설정을 별도로 준비한다. 링크 자체나 비밀 값은 커밋하지 않는다.

## 화면이 보여주는 것

- 실제 모델 호출의 시작·완료, 모델이 도구에 전달한 검색어
- 왕·연도·월 필터와 실제로 선택된 검색 분기
- BM25가 실행될 때만 실제 추출어 표시: Okt 실패 시 정규식 대체임을 표시
- 벡터·키워드·필터 검색 결과의 순서와 기록 본문 일부
- 실제 RRF 순위 통합과 시간순 정렬이 실행됐을 때 해당 이벤트 표시
- 모델에 전달한 최종 기록 목록, 수량, 경과 시간

`세종`, `세종 건강`, `훈민정음`처럼 질문을 달리해 검색 경로 차이를 확인할 수 있다.
LLM이 질문을 재작성할 수 있으므로 화면에 표시된 실제 도구 검색어가 분기를 결정한다.
왕 이름이 있는 질문에서는 OKT/BM25를 거치지 않을 수 있다.

RRF는 별도 reranker 모델이 아니라 검색 목록의 순위를 통합하는 기존 알고리즘이다.
실행되지 않은 정리 단계는 완료 시 흐리게 표시한다. 카드 번호는 해당 목록의 순서이며 관련성 점수가 아니다.
후보는 최대 8개, 최종 근거는 최대 20개를 미리보기로 표시하고 전체 개수는 별도로 표시한다.
각 카드 본문은 앞 360자다. 같은 본문에는 같은 해시 ID를 부여한다.

진행 시간은 서버에서 이벤트를 전달할 때의 누적 시간이다. 단계별 GPU 연산 시간이나 모델 내부 사고 과정이 아니다.
진행 표시를 위한 추가 LLM 호출이나 인위적인 단계 지연은 없다. 완성 답변을 받은 뒤 출력하며 토큰 단위 출력은 구현하지 않았다.

## 변경 범위

`POST /chat/stream`이 SSE 이벤트를 전송한다. 기존 `/chat`도 유지한다.
MCP 도구의 요청별 progress 알림을 사용하므로 stdout에 추적 로그를 섞지 않는다.
모델 호출은 작업 스레드에서 실행해 이벤트 전달을 막지 않는다. MCP 검색도 요청별 ContextVar를 전달한 작업 스레드에서 실행한다.
브라우저 연결 종료 시 해당 스트림 작업을 취소한다. 이미 실행 중인 동기 모델·검색 스레드의 연산까지 즉시 중단되는 것은 아니다.
브라우저는 5분 후 응답 대기를 중단한다. 오류·통신 단절 시 완료 상태로 표시하지 않으며 실패한 대화는 대화 이력에 추가하지 않는다.

검색 알고리즘·모델·인덱스·추가 유료 호출은 변경하지 않았다. 이번 구현은 챗봇 질문 흐름에 적용되며 사진 업로드 흐름은 추적하지 않는다.

## 오프라인 검증

```bash
PYTHONDONTWRITEBYTECODE=1 demo_env/bin/python -m unittest discover -s tests -v
node tests/test_pipeline.cjs
node --check frontend/static/pipeline.js
node --check frontend/static/script.js
```

Python 테스트는 실제 MCP 세션을 사용하되 모델·인덱스는 작은 모의 객체로 대체한다.
세 분기, 요청 분리, BM25/DB 누락, fallback, 시간 정렬, 이벤트 선행 전달, 연결 종료, 이력/오류 처리를 검증한다.
프런트엔드는 작은 DOM 모형으로 스트림 파서를 실행해 한글/프레임 분할, 기록, 미실행 단계, 안전한 텍스트 표시와 오류 처리를 검증한다.
실제 화면 렌더링 검증이나 실제 LLM 품질 검증을 대체하지 않는다.

## 2026-11-04 검증 기록

- Python 오프라인 검증 8개 통과, 프런트엔드 검증 통과, Python/JavaScript/shell 문법 검사와 Git 공백 검사 통과.
- 작은 모의 데이터에서 기존 브랜치와 검색 결과 문자열을 7개 질문으로 비교해 모두 일치.
- 실제 HTTP + 실제 MCP 세션 + 모의 모델/기록을 연결해 첫 진행 이벤트 0.143초, 최종 결과 1.578초로 이벤트 선행 도착 확인. 실제 모델 응답 성능 측정이 아니다.
- 기존 로컬 자산으로 실제 앱 부팅 확인: FAISS, BM25 195,055개 청크, Okt 로드 성공. HTML/JS 제공과 실제 MCP 명언 도구 응답 확인.
- 실제 LLM 추론은 호출하지 않았다. 브라우저 자동화 도구가 응답하지 않아 시각적 레이아웃 검증은 완료하지 못했다. 실제 시연 환경에서 질문→답변과 화면 배치는 추가 확인이 필요하다.
- 검증용 서버는 종료했다. 위 실행 명령으로 실제 앱을 시작할 수 있다.
